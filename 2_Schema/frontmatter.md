# Frontmatter Field Specification

The measured inventory of YAML frontmatter fields used across the vault: required / optional / deprecated, what each field is for, and which files use it.

---

## 1. 1_Wiki entries (compiled knowledge)

| Field | Required | Notes |
|-------|----------|-------|
| `title` | Yes | Entry title, in double quotes if it contains special chars |
| `type` | Yes | Matches the containing directory: `concept` / `entity` / `comparison` / `framework` / `resource` |
| `created` | Yes | `YYYY-MM-DD` |
| `source` | Yes | Full path of the source file(s). Compilation traceability. |
| `confidence` | Yes | `high` / `medium` / `low` |
| `tags` | Yes | ≥ 3 tags: type + topic + PARA category |
| `aliases` | Optional | Alias array to reduce navigation ambiguity |
| `author` | Yes | `agent` — entries compiled by AI are authored by the compiling agent (this release never uses a personal handle) |
| `entity_kind` | Required for entities | `person` / `organization` / `project` / `product` |

Example:

```yaml
---
title: "Attention Economics"
type: concept
created: 2026-09-15
source: 0_Inbox/clippings/xiaojian-guo-monitor-episode.md
confidence: high
tags:
  - concept
  - media
  - para/resource
aliases:
  - attention economy
author: agent
---
```

## 2. 0_Inbox / diary

| Field | Required | Notes |
|-------|----------|-------|
| `processed` | Recommended | Three-state: `false` = uncompiled (the scan target); `true` = compiled (skip); `skip` = **never compiled** — every compile/iteration flow skips it unconditionally. Scanning also picks up files missing the field |
| `abstract` | Optional | One-line summary for quick preview |
| `weekly_reviewed` | Optional | Date value `YYYY-MM-DD` of the weekly review that covered this note (not `true`) |

## 2b. 0_Inbox / chat-distill (distilled AI conversations)

Landed raw notes in `0_Inbox/chat-distill/` (via `/chat-distill`) add traceability fields on top of the diary set:

| Field | Required | Notes |
|-------|----------|-------|
| `title` | Yes | `"Distilled: <topic>"` |
| `author` | Yes | `agent` (compiled by the distilling agent) |
| `created` | Yes | `YYYY-MM-DD` |
| `tags` | Yes | `chat-distill` + `inbox/raw` |
| `processed` | Yes | starts `false`; flipped `true` after compilation |
| `source_type` | Yes | `chat` |
| `source_agent` | Yes | the AI client the conversation came from (fill in the agent name; placeholder `agent`) |
| `source_file` | Yes | path of the original conversation log |
| `source_time` | Yes | `YYYY-MM-DD` of the conversation |

## 2c. Source / clipping drafts

Metadata carried by raw drafts and clipped content; AI reads it during compilation but does not enforce it.

| Field | Required | Notes |
|-------|----------|-------|
| `date` | Optional | Writing / publish date of a sourced draft, independent of `created` (which is the file creation date) |
| `category` | Optional | Draft category; overlaps with tags, kept in the draft context |
| `url` | Optional | Source link of a clipping / note, for traceability |
| `published` | Optional | Publish platform / time marker of clipped content |
| `description` | Optional | Clipping summary, mostly used on tool-intro pages |

## 3. Config / system fields

| Field | Notes |
|-------|-------|
| `updated` | Last-updated date of long-lived maintained docs (index, schema, workflow files) |
| `source_skill` | Which skill produced the document (per the output-file spec, see TheSchema §6) |
| `excalidraw-plugin` | Auto-generated by the Excalidraw plugin; records canvas version and JSON state. **Managed by the plugin — do not delete.** |

## 4. Deprecated fields

| Field | Status | Replacement |
|-------|--------|-------------|
| `related` | Deprecated | Links go in the `## See also` section at the end of the entry |
| `links` | Deprecated | Same as above |

## 5. Usage suggestions

1. **New 1_Wiki entry**: fill all core fields in §1; add `aliases` when the title contains spaces or English variants.
2. **Add fields cautiously**: every new field raises vault-wide maintenance cost; until a second user appears, merge it into `tags`.
3. **Keep `source`**: it is the key to compilation traceability — without it AI cannot trace back to the raw material.
4. **Inter-entry links go only in the trailing `## See also` section**, each with one of the 8 type labels (see TheSchema §3); an unlabeled link is not written. `related` / `links` no longer appear in frontmatter.
5. **Leave `excalidraw-plugin` alone** — the plugin manages it; deleting it breaks the canvas.

> The authoritative field spec for entries is TheSchema.md §4; this file is the measured inventory and usage notes.
